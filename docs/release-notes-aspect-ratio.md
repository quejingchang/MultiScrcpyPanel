## ⚠️ 请先看这一条（重要）

> **如果你更新后启动，发现卡片还是原来"又矮又胖"的样子 —— 不是没生效，是旧配置把新默认值盖住了。**
>
> **解决办法：关掉 MultiScrcpyPanel，删除程序目录下的 `config/settings.json`，再重新启动。**
> 程序会自动按新默认值重新生成这个文件。
>
> 说明：`config/settings.json` 里存着上一版写入的旧卡片尺寸（300×560），程序启动时**文件里的值优先于程序内置默认值**，所以只要这个文件还在、里面还是旧数字，改多少代码都看不到效果。
>
> 如果你不想丢失里面的截图目录等个性化设置，也可以只把这两行手动改成：
>
> ```json
> "CardBaseWidth": 240,
> "CardBaseHeight": 600
> ```
>
> （本次交付已经帮你把开发目录 `MultiScrcpyPanel\bin\x64\Debug\net8.0-windows\config\settings.json` 改好了，原文件备份在同目录的 `settings.json.bak`。）

## 1. 这次改了什么

一句话：**把投屏卡片从"矮胖"改成"瘦高"，让它贴合现在手机的长屏比例，画面两侧的大黑边基本消失。**

| 指标 | 改动前 | 改动后 | 变化 |
| --- | --- | --- | --- |
| 卡片默认尺寸 | 300 × 560 | **240 × 600** | 更窄更高 |
| 画面可绘区 | 296 × 466 | **236 × 506** | — |
| 画面区宽高比 | 0.635 | **0.466** | 贴合长屏 |
| 9:19.5 机型左右黑边 | 81px（占 **27.4%**） | 约 3px（占 **1.0%**） | **黑边几乎消失** |
| 9:19.5 机型实际画面 | 215 × 466 | **233 × 506** | **画面面积 +17.7%** |
| 1920 宽窗口最大化，单行能放几张卡 | 6 张 | **7 张** | **+1 张** |
| 1366 宽窗口最大化，单行能放几张卡 | 4 张 | **5 张** | **+1 张** |

**额外的隐性好处**：画面区变窄后，程序下发给解码器的目标尺寸更贴近手机真实比例，缩放时要处理的像素反而变少了，所以 8 台同屏的 CPU 开销**不升反降**。

## 2. 想自己微调？（支持）

卡片尺寸是**开放给你自己改**的。关掉程序，编辑 `config/settings.json` 里这两个字段，保存后重启即可：

```json
"CardBaseWidth": 240,
"CardBaseHeight": 600
```

| 想要的效果 | 推荐值 | 代价 |
| --- | --- | --- |
| 默认（推荐） | `240` / `600` | 平衡 |
| 画面再大一点 | `252` / `630` | 画面约 +32%，但卡片更高，1440p 以下的屏幕可能需要滚动 |
| 一屏塞更多设备 | `216` / `540` | 单行能多放 1~2 张，画面变小 |

> 小提示：宽高比保持在 **0.43 ~ 0.50** 之间最贴合主流长屏手机（算法：`(宽−4) ÷ (高−94)`）。

## 3. 已知问题（本版没修，先说清楚）

### 3.1 50% 缩放档画面偏胖 —— 这是老问题，不是这次改出来的

- **现象**：切到 50% 档时，画面比例明显不对（偏胖），约 0.76。
- **原因**：50% 档卡片宽度算出来是 120px，但程序里有个"最小宽度 160px"的硬性下限把它顶到了 160，而高度 300px 没被下限影响 —— 一边被撑、一边没被撑，比例就歪了。
- **重要说明**：**这个问题在本次改动之前就存在**（旧版该档比例是 0.84，比现在还差）。本次改动让它从 0.84 变成 0.76，**是改善，但没有根治**。
- **计划**：已排入下一版修复（等比钳制下限）。

> 建议日常使用 **75% 及以上**档位，75/100/150/200% 四档比例均正常。

### 3.2 平板和横屏设备，黑边会变大

本版**只针对长屏手机做优化**。如果你接的是平板（4:3 竖屏）或横屏使用的设备，新比例下上下黑边会比以前更明显。平板/横屏的自适应排在后续版本，本版明确不处理。

### 3.3 本版没有新增 25% / 300% 缩放档

缩放档位仍然是 **50% / 75% / 100% / 150% / 200%** 五档，未做增减。

### 3.4 「重新授权」按钮在 75% 档文字显示不全 —— 同样是老问题

- 该按钮只在设备未授权时才出现。
- 实测：**改动前**在 75% 档就已经显示不全（能画 36px，需要 48px）；改动后更紧张。
- **100% 档下显示完整**，不影响正常使用；已记录，待后续版本一并处理（建议改为「授权」二字）。

## 4. 按键区文案：「多任务」已改为「任务」

卡片变窄后按钮也跟着变窄，实测发现 75% 档的「多任务」会被切掉一个字。

| 档位 | 按钮可用宽 | 「多任务」需要 | 结果 |
| --- | --- | --- | --- |
| 100% | 54px | 36px | 完整显示 ✅ |
| 75% | 39px | 36px | **被切掉约一个字** ❌ |

**处理**：把该按钮文案改为**「任务」**（2 字，75% 档下完整显示）。功能完全不变，鼠标悬停仍会显示完整说明「多任务 · APP_SWITCH（KEYCODE_APP_SWITCH）」。

其余 7 个按钮（主页 / 返回 / 电源 / 音量- / 音量+ / 截图 / 重新授权）在 **100% 档全部显示完整**。

## 5. 建议你这样自测

1. **删除 `config/settings.json` 后重启**（或确认里面已是 240 / 600）。
2. **接一台长屏手机**（如 1080×2340），看 100% 档下画面两侧 —— 应该几乎看不到黑边了（理论仅 3px）。
3. **依次切换 75% / 100% / 150% / 200% 四档**，确认：
   - 画面**不拉伸**（人脸、文字不变形）；
   - 按钮文案不缺字，第 3 个按钮显示为「任务」。
4. **切到 50% 档**：画面会偏胖，这是上面 §3.1 说明的老问题，属预期。
5. **窗口最大化**（1920 宽），数一下单行能放几张卡片 —— 应为 **7 张**。
6. **多接几台设备跑一会儿**，确认没有卡片错位、没有崩溃。

## 7. 附：技术细节（不感兴趣可跳过）

```text
画面区宽  imgW   = 卡片宽  − 4      // 4  = 边框(1×2) + 内边距(1×2)
画面区高  imgH   = 卡片高  − 94     // 94 = 4 + 标题栏 26 + 按键区 64
画面区比例 r_card = imgW / imgH      // 本版目标 ≈ 0.466

黑边占比：
  设备比例 < 画面区比例 → 左右黑边占比 = 1 − r_dev / r_card
  设备比例 > 画面区比例 → 上下黑边占比 = 1 − r_card / r_dev

按键列宽   = (卡片宽 − 8) / 4       // 8 = 4 + 按键面板内边距(2×2)
按钮实绘宽 = 列宽 − 4                // 按钮外边距(2×2)
```
